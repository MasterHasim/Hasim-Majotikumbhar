- Live smoke test against the real spreadsheet caught a real bug: `ReferenceError: SheetRepository is not defined` when running `NumberRepository` in the Apps Script editor, even though `node tests/phase2-repository-verification.js` passed. Root cause: Apps Script concatenates `.gs` files in filename-alphabetical order, and `class NumberRepository extends SheetRepository` is evaluated at file-load time — `Phase2Repositories.gs` sorted *before* `Phase2Repository.gs` alphabetically (`"Repositories" < "Repository"`, since `i` < `y`), so `SheetRepository` didn't exist yet. The Node test hadn't caught it because it loaded files in a hand-picked safe order instead of mimicking Apps Script's real order.
- Fix: renamed `src/Phase2Repository.gs` → `src/Phase2Persistence.gs` (sorts before `Phase2Repositories.gs`); updated `tests/phase2-repository-verification.js` to load every `.gs` file in `src/` sorted alphabetically, matching Apps Script's actual behavior, so this class of bug is caught locally going forward.
- Second bug caught by the same live smoke test: `NumberRepository.create()` wrote `phoneNumber: '000'` but reading it back returned the number `0` — Google Sheets silently coerces numeric-looking strings into real numbers on write, which would corrupt phone-number-style IDs. Fixed in `src/Phase2Persistence.gs`'s `appendRow_`/`writeRow_`: applying `Range.setNumberFormat('@')` once at sheet creation, and even calling it on the exact write range via `getRange().setValues()` instead of `sheet.appendRow()`, were each insufficient on their own — only applying `setNumberFormat('@')` directly on the exact target range immediately before `setValues()`, every write, reliably prevented the coercion. Re-verified live: `readBack.phoneNumber` came back as `"000"` (string), full create→read→count→remove cycle correct.
